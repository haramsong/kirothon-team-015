# 기획서: 1인 가구 냉장고 관리 서비스 (서비스명 미정)

- 상태: 초안
- 기준 문서: `.kiro/steering/product.md` (제품), `.kiro/steering/tech.md` (기술 제약)
- 용도: Kiro 스펙(requirements → design → tasks)의 입력. API 스키마, DB 구조, 코드는 design 단계에서 정한다.
- 본문은 7장 열린 질문의 추천안을 적용한 상태로 썼다. 다른 선택지를 고르면 해당 화면 기획을 고친다.

## 1. 개요

### 1.1 한 줄 소개

영수증이나 온라인 주문내역을 찍으면 냉장고 재고가 채워지고, 소비기한이 임박한 재료로 만들 메뉴를 추천받아 요리하면 쓴 재료가 자동으로 빠지는 서비스

### 1.2 대상 사용자

혼자 사는 직장인과 대학생 (1인 가구)

- 2024년 1인 가구는 804만 5천 가구로 전체 가구의 36.1%이며, 그중 약 60%가 취업 상태다. (출처: 국가데이터처, 「2025 통계로 보는 1인가구」)

### 1.3 핵심 차별점

기존 냉장고 앱은 재료를 넣는 일을 영수증 스캔으로 쉽게 만들었지만, 다 먹은 재료를 빼는 일은 사용자가 직접 해야 한다. 이 서비스는 등록, 추천, 요리, 차감을 하나의 흐름으로 묶어 재고 목록이 실제 냉장고와 계속 맞도록 한다.

| 순서     | 차별점                                       | 해결 방식                                                                                            | 화면에서 보여줄 것                                         |
| -------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 1 (대표) | 요리하면 재고가 알아서 줄어든다              | 추천 레시피에 사용 재료와 수량(개)이 함께 나온다. "요리했어요"를 누르면 확인을 거쳐 재고에서 빠진다. | 차감 확인에서 "양파 8개 → 7개"                             |
| 2        | 종이 영수증이 없어도 사진 한 장으로 등록한다 | 마트 영수증 사진과 온라인 주문내역 스크린샷을 같은 업로드 버튼 하나로 인식한다.                      | 업로드 화면에 "영수증 사진 또는 주문내역 캡처" 명시        |
| 3        | 대용량 재료를 끝까지 쓰는 3일 식단           | 임박 재료를 3일 안에 다 쓰도록 끼니별 메뉴를 짠다.                                                   | 재료별 지금 수량과 3일 뒤 남는 수량 (예: "양파 8개 → 0개") |

- 시간이 부족하면 차별점 1 → 2 → 3 순서로 지킨다.
- 기존 앱 비교는 product.md의 비교표를 따른다. 그 표의 "확인 필요"는 앱스토어 설명에 언급이 없다는 뜻이며, 기능이 없다는 확인이 아니다. 발표 전에 각 앱을 설치해 직접 확인한다. (7장 Q12)

### 1.4 범위 밖

product.md의 범위 밖 항목은 이 문서의 어느 화면에도 넣지 않는다.

- 회원가입, 로그인, 여러 사용자 간 공유
- 푸시 알림
- 바코드 스캔
- 영양 정보, 칼로리 계산
- 장보기 목록, 쇼핑몰 연동

## 2. 화면 목록

화면 4개와 모달 2개로 구성한다.

- 한 끼 추천은 별도 화면을 두지 않는다. 레시피 화면(S3)이 메뉴 추천부터 시작한다.
- product.md의 "차감 확인 화면"은 레시피 화면 위에 뜨는 모달(M2)로 만든다.
- 품목 수정과 추가는 냉장고 목록(S1)과 재료 등록(S2)이 같은 모달(M1)을 함께 쓴다.

| ID  | 이름        | 형태           | 목적                                                                     | 핵심 기능 | 관련 차별점        |
| --- | ----------- | -------------- | ------------------------------------------------------------------------ | --------- | ------------------ |
| S1  | 냉장고 목록 | 화면 (첫 화면) | 지금 가진 재료와 남은 일수를 확인하고 다음 행동을 고른다                 | 3         | 1 (차감 결과 반영) |
| S2  | 재료 등록   | 화면           | 영수증 사진이나 주문내역 캡처로 재료를 인식하고, 확인·수정한 뒤 저장한다 | 1, 2      | 2                  |
| S3  | 레시피      | 화면           | 메뉴의 사용 재료와 조리 단계를 보고, 요리 후 차감을 시작한다             | 4, 5      | 1                  |
| S4  | 3일 식단    | 화면           | 임박 재료를 3일 안에 다 쓰는 끼니별 메뉴와 재료별 남는 수량을 확인한다   | 5         | 3                  |

| M2  | 차감 확인   | 모달 (S3)      | 쓴 품목과 수량을 고치고, 바뀌는 수량을 확인한 뒤 차감한다                | 4, 5      | 1                  |

이동 구조:

- S1이 중심 화면이다. S2, S3, S4는 왼쪽 위 뒤로 버튼으로 돌아간다.
- 하단 탭은 두지 않는다.

```
S1 냉장고 목록 ─┬─ "재료 등록" ──→ S2 재료 등록 ── 품목 행 탭 → M1 품목 편집
               ├─ "한 끼 추천" ──→ S3 레시피 (추천 모드) ── "요리했어요" → M2 차감 확인
               ├─ "3일 식단" ───→ S4 3일 식단 ── 끼니 카드 탭 → S3 레시피 (식단 모드)
               └─ 품목 행 탭 ───→ M1 품목 편집
```

## 3. 전체 사용자 흐름

### 흐름 A: 첫 방문과 영수증 등록

```
S1 냉장고 목록 (빈 상태)
  → "재료 등록" 탭
  → S2 업로드 단계: "영수증 사진 또는 주문내역 캡처 올리기" 탭 → 이미지 선택
  → S2 인식 중 (로딩)
  → S2 인식 결과: 품목 행 탭 → M1에서 수량·소비기한 등 수정 → "저장"
  → "냉장고에 저장" 탭
  → S1 냉장고 목록 (남은 일수 순, 임박 재료 강조) + 토스트 "8개 품목을 냉장고에 넣었어요"
```

- 인식 실패: S2 에러 상태 → "다시 시도", "다른 이미지 올리기", "직접 입력하기" 중 선택

### 흐름 B: 주문내역 캡처로 추가 등록

```
S1 → "재료 등록" → S2 같은 업로드 버튼으로 주문내역 스크린샷 선택
  → 인식 중 → 인식 결과 확인·수정 → "냉장고에 저장"
  → S1 (같은 이름의 품목은 합쳐진 목록)
```

### 흐름 C: 한 끼 추천 → 요리 → 차감 → 목록 반영

```
S1 → "한 끼 추천"
  → S3 추천 모드: 메뉴 고르는 중 (로딩, 임박 재료 칩 표시)
  → 메뉴 이름 + 사용 재료와 수량 표시 → 레시피 단계 불러오는 중 → 단계 표시
  → (다른 메뉴를 원하면 "다른 메뉴 추천" → 다시 로딩)
  → "요리했어요" 탭
  → M2 차감 확인: 사용량 −/+ 수정, 안 쓴 품목 체크 해제 → "양파 8개 → 7개" 확인
  → "차감하기" 탭
  → S1 냉장고 목록 (양파 7개, 0개 이하가 된 품목은 사라짐) + 토스트
```

- M2에서 "취소": 모달만 닫히고 재고는 그대로다.

### 흐름 D: 3일 식단

```
S1 → "3일 식단"
  → S4 식단 짜는 중 (로딩)
  → 재료별 요약 ("양파 8개 → 0개") + 끼니 카드 6개
  → 끼니 카드 탭
  → S3 식단 모드: 메뉴 이름·사용 재료 바로 표시 → 레시피 단계 불러오는 중 → 단계 표시
  → "요리했어요" → M2 차감 확인 → "차감하기"
  → S4 3일 식단 (그 끼니에 "요리 완료") + 토스트
  → "← 냉장고" → S1 (차감 반영)
```

### 흐름 E: 냉장고 목록에서 직접 수정

```
S1 → 품목 행 탭 → M1 → 값 수정 후 "저장" 또는 "삭제" → S1 반영
```

## 4. 화면별 상세 기획

### 4.0 화면 공통 규칙

- 수량 표기: "8개"처럼 개수로 쓴다. 0.5개 단위는 "7.5개"로 쓴다. 재고와 레시피 사용량 모두 같은 단위다.
- 소비기한 표기: 날짜와 남은 일수를 함께 쓴다 ("4/12 · D-2"). 오늘이면 "D-day", 지났으면 "지남"으로 쓴다. "유통기한"이라는 말은 쓰지 않는다.
- "예상" 표시: LLM이 추정한 소비기한 옆에 "예상"을 붙인다. 사용자가 직접 고치면 뗀다. (Q10)
- 임박 기준: 남은 일수 3일 이하(D-3 ~ D-day)를 임박으로 강조한다. 소비기한이 지난 품목은 "지남"으로 따로 표시한다. (Q1)
- 추천 기준 (한 끼 추천, 3일 식단 공통):
  - 임박 재료를 먼저 쓴다. 임박 재료가 없으면 소비기한이 빠른 재료부터 쓴다.
  - 소비기한이 지난 품목은 쓰지 않는다. (Q1)
  - 냉장고 재고와 기본 양념만 쓴다. (Q7)
  - 레시피는 1인분 기준이다. (Q8)
- 기본 양념: 소금, 설탕, 간장, 식용유, 후추, 참기름, 식초, 고춧가루. 재고에 없어도 있다고 가정하고 차감하지 않는다. 영수증에 있으면 인식 단계에서 뺀다. (Q6)
- 차감:
  - M2에서 사용자가 "차감하기"를 누른 뒤에만 적용한다.
  - 차감 후 0개 이하가 된 품목은 목록에서 뺀다.
  - 여러 품목 차감은 전부 적용되거나 전부 적용되지 않아야 한다.
- LLM 대기: 요청 중에는 같은 요청을 다시 보내는 버튼을 비활성으로 둔다. LLM을 부르는 모든 단계에 "다시 시도"를 둔다.
- 화면 형태: 모바일 폭 한 열 레이아웃. 데스크톱 브라우저에서는 가운데 정렬로 보여준다. (Q11)

LLM이 만든 값과 수정 위치:

| LLM이 만든 값         | 처음 나오는 곳 | 수정하는 곳          | 수정 방법                             |
| --------------------- | -------------- | -------------------- | ------------------------------------- |
| 품목명                | S2 인식 결과   | M1 (S1, S2에서 열림) | 글자 입력                             |
| 수량(개)              | S2 인식 결과   | M1                   | 숫자 입력, −/+ 0.5개 단위             |
| 보관 위치             | S2 인식 결과   | M1                   | 냉장/냉동/실온 중 선택                |
| 소비기한              | S2 인식 결과   | M1                   | 날짜 선택                             |
| 추천 메뉴의 사용 품목 | S3, S4         | M2                   | 체크 해제, 재고에서 품목 추가         |
| 추천 메뉴의 사용 수량 | S3, S4         | M2                   | −/+ 0.5개 단위                        |
| 추천 메뉴 자체        | S3, S4         | S3, S4               | "다른 메뉴 추천"(S3), "다시 짜기"(S4) |

기획에 영향을 주는 기술 제약 (tech.md):

- 이미지는 올리기 전에 브라우저에서 긴 변 1568px 이하 JPEG로 줄인다 (Lambda 6MB, Bedrock 이미지 3.75MB 제한). 사용자에게 따로 보이는 단계는 없고 인식 로딩에 포함된다.
- 서버 요청 하나는 29초 안에 끝나야 한다. 그래서 메뉴 이름과 사용 재료를 먼저 받고, 레시피 단계는 따로 받는다. S3가 두 단계로 로딩되는 이유다.
- 로그인이 없어 브라우저마다 냉장고가 따로 생긴다. 시크릿 창이나 다른 브라우저에서는 빈 냉장고로 시작한다.
- 배포 환경에 문제가 생기면 로컬 실행(Vite + uvicorn)으로 데모를 녹화한다.

### 4.4 S3 레시피

| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 목적               | 메뉴의 사용 재료와 조리 단계를 보고, 요리를 마치면 "요리했어요"로 차감을 시작한다.                                                                                                                                                                                                                                                                                                                            |
| 진입 경로          | - 추천 모드: S1 "한 끼 추천". 메뉴 추천부터 시작한다.<br>- 식단 모드: S4 끼니 카드 탭. 메뉴와 사용 재료는 식단에서 정해진 값을 쓰고, 레시피 단계만 새로 받는다.                                                                                                                                                                                                                                               |

"다른 메뉴 추천" (추천 모드) → 방금 메뉴를 빼고 다시 추천 → 로딩 → 새 메뉴 (Q2)<br>3. 뒤로 버튼 → 차감 없이 나간다                                                                                                                                                  |
| 수정 가능한 LLM 값 | 사용 품목과 수량은 이 화면에서 보기만 하고, "요리했어요" 뒤 M2에서 고친다. 메뉴는 "다른 메뉴 추천"으로 바꾼다. 조리 단계 문장은 고치지 않는다.                                                                                                                                                                                                                                                                |

| 에러 상태          | - 메뉴 추천 실패·시간 초과: "메뉴를 추천하지 못했어요" + "다시 시도"<br>- 레시피 단계 실패: 메뉴와 재료는 그대로 두고 단계 자리에 "조리 순서를 불러오지 못했어요" + "다시 불러오기". ### 4.5 M2 차감 확인 (모달)

| 항목               | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 목적               | 이번 요리에 실제로 쓴 품목과 수량을 고치고, 재고가 어떻게 바뀌는지 확인한 뒤 차감한다.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 진입 경로          | S3 "요리했어요" (추천 모드, 식단 모드 공통)                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 주요 요소          | - 제목 "쓴 재료 확인"<br>- 안내 "실제로 쓴 만큼 고친 뒤 차감하세요"<br>- 품목 행 (S3 사용 재료가 초기값): 체크박스, 품목명, 사용량 −/+ (0.5개 단위), 변화 표시 "8개 → 7개" (지금 수량 → 차감 후 수량, 차감 후 수량을 굵게)<br>- 차감 후 0개 이하가 되는 행: "0개 · 목록에서 빠져요"<br>- 재고에 없는 품목 행: 회색, "재고에 없음 · 차감 안 함"<br>- "재고에서 품목 추가": 냉장고 품목 중 아직 목록에 없는 것을 고르는 선택 상자<br>- 안내 "기본 양념은 차감하지 않아요"<br>- 버튼: "차감하기 (3개 품목)", "취소" |

## 5. 데모 시나리오

목표 길이는 3분 이내다. 단계 합계는 2분 50초이고 10초를 여유로 둔다. 예상 시간에는 LLM 대기 시간이 포함되며, 리허설에서 실측한 뒤 고친다.

### 5.1 녹화 준비

- 시크릿 창에서 시작한다. 새 기기 ID가 만들어져 빈 냉장고로 시작한다.
- 마트 영수증 사진 1장: 양파 1.5kg망과 소비기한이 짧은 품목(두부, 우유 등)이 들어 있고, 구매일이 녹화일보다 2~4일 앞선 것. 그래야 임박 재료가 자연스럽게 생긴다.
- 온라인 주문내역 캡처 1장: 식재료 3~5개.
- 예비 영수증 1장, 예비 캡처 1장. 네 장 모두 녹화 전에 인식 결과를 확인해 둔다.
- 단계별 성공 장면을 미리 녹화한 예비 클립.
- 배포 환경에 문제가 있으면 로컬 실행(Vite + uvicorn)으로 녹화한다.
- LLM 대기 구간은 실제로 녹화한다. 길면 편집에서 배속하고 화면에 "2배속"이라고 표시한다.

- 추천: B. A보다 조금 더 만들지만 3일 식단을 따라 요리하는 흐름이 생긴다. C는 저장할 대상이 늘어 6시간 안에서는 부담이 크다. 6장의 3-2를 빼면 이 질문은 필요 없어진다.

### Q5. 같은 품목을 다시 등록할 때 (S2 저장)

- A. 이름이 같으면 한 행으로 합친다. 수량은 더하고 소비기한은 더 빠른 날짜를 남긴다.
- B. 등록할 때마다 따로 저장한다. 차감할 때 어느 행에서 뺄지 정해야 한다.
- 추천: A. 차감 대상이 한 행이라 M2가 단순하고, 빠른 소비기한을 남기면 임박 표시가 늦어지지 않는다. 단, 이름이 정확히 같아야 합쳐지므로 인식 단계에서 품목명을 일반 명칭으로 정리해야 한다 (예: "국산 양파 1.5kg" → "양파").

### Q6. 기본 양념 범위와 영수증에 있는 양념 처리 (S2, S3, M2)

- 범위: A. product.md의 4종(소금, 설탕, 간장, 식용유)만 / B. 4종 + 후추, 참기름, 식초, 고춧가루 (8종 고정) / C. 목록 없이 LLM이 판단

- 추천: B + 가. 목록이 고정돼야 S3의 "기본 양념 (차감 안 함)" 줄과 차감 결과가 일치한다. 등록만 하고 차감하지 않으면 목록에 계속 남아 실제 냉장고와 어긋난다.

### Q7. 재고에 없는 재료를 레시피에 허용할지 (S3, M2)
